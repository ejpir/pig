A little less remembering.

Keep the schedule separate from its runs. Edit the recurring instruction once; open any occurrence as a normal Pi session.

  1. Open Morning review. Pause and resume its future runs.
  2. Try Run now. An explicit confirmation comes before a new session.
  3. Create a schedule. Change the time or use a numeric, five-field cron expression.
  4. Review the next runs, then explicitly allow unattended execution.
  5. Check the offline and setup screens. Cached information is never presented as live state.

This file is a local prototype. Buttons only change sample data; nothing connects to a computer, executes a prompt or installs a service.

Schedules aren’t sessions.

A schedule describes repeatable work. Each occurrence opens a fresh session, with its prompt and settings saved. Pausing the schedule does not stop a run already in progress.

Quiet, predictable defaults.

No overlapping runs. Skip missed times rather than build a backlog. Keep the timezone explicit, with calendar previews before enabling. Recovery never blindly repeats interrupted unsafe commands.

Honest when the phone is away.

The host owns timing and history. A lost phone connection doesn’t stop the host. An unreachable computer has unknown status—not a promise that its scheduler is still working.
