## Highlights

Pi and the Durable backend are upgraded to **1.2.0**. Android gains experimental native JavaScript visuals, inline HTML previews, and input/lifecycle improvements. **Swarm now defaults off.**

### Backend and swarm settings

- Pin stock Pi and the Earendil Durable dependencies to stable 1.2.0, with verified upstream release checksums. Adapt Durable tool results to the new `output` API, including images, subagents and peer mailboxes.
- New sessions and older sessions without a saved Swarm preference default to **disabled**. Explicitly saved enabled preferences remain enabled. The session switch controls only new swarm admission; disabling it does not stop admitted crews or ordinary subagents.
- Preserve complete frozen subagent answers for reports and chains while keeping app previews bounded. Expand crash/recovery, lifetime and mailbox tests.

### Android native visuals — experimental

- `@Visualize` requests a plain `javascript pi-visual` program with native controls and bounded vector canvases. No HTML, WebView, Node process or per-visual Rust build is used for this feature. Ordinary JavaScript fences remain inert.
- Fresh QuickJS-NG contexts for initialization and callbacks, transactional flat state, cancellation rollback, guarded drawing, bounded caches and display-driven animation. Source, heap, stack and cooperative execution limits are in-process safeguards, **not OS isolation or hard real-time guarantees**.
- Defer transcript projection during native manipulation while allowing local controls, drawing and animation to continue. Cancel hidden/unfocused interactions safely and reject stale mount work.
- **Migration:** JSON/Rhai visuals no longer execute. Original source and saved data are retained; regenerate with `@Visualize` for the JavaScript format. Changed source has a separate local state identity.

### Inline pages — a separate feature

- Explicitly admitted HTML artifacts can run inline in chat. Expansion preserves the running document; adopting a revised page is explicit. Source and separate viewing remain available, and a failed preview requires Retry.
- Inline WebView restrictions are separate from native visuals and do not apply universally to legacy posters or separate page viewers. This remains an experimental browser-backed feature.

### Input, lifecycle and diagnostics

- Shared composer layout for direct subagent input, integrated Working/Stop presentation, and IME/caret corrections.
- Return normally from the Android native Activity instead of terminating the process. Scope Java events to Activity generations and retire frame-clock/dispatcher work with explicit shutdown handling and late-wakeup protections.
- Add opt-in, fixed-label CPU traces and focus-checked isolated capture/recreation tooling. Emulator coverage requires native return, distinct Activity identities and actual control changes—not merely a surviving PID.

### Validation and limitations

Rust workspace tests and strict Clippy, Durable type checking and 103 unit/integration tests, stock Pi metadata transport, Durable recovery/permission/auth/scheduler integration, and packaging/tooling checks were exercised locally. Release CI validates the platform packages and APK.

Physical-device lifecycle validation remains incomplete. These changes do **not** establish that the historical HWUI destroyed-mutex crash is fixed, physical presentation FPS, universally bounded shutdown, or complete resource reclamation. Unsafe late executor residues may intentionally remain inert rather than be destroyed on the wrong thread or inside reentrant producer callbacks.
