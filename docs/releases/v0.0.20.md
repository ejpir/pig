## Highlights

**Android now includes a retained source workspace and isolated remote terminals, along with continuous in-place chat selection and more natural scrolling around rendered pages.**

### Edit source files on Android

- Open an editor workspace from the computer menu, choose its folder independently from the active chat project, and move between chat and the editor without losing either draft.
- Up to eight open file buffers retain their text, selection, and scroll position. Folder changes, computer changes, closing the editor, and leaving a computer are blocked while any draft, conflict, or unresolved save is present.
- Files up to 128 KiB can be edited and saved explicitly. Files up to the helper's 1 MiB text limit get a bounded read-only preview above that size; unsupported larger files fail closed. CRLF files keep CRLF when saved; mixed or legacy line endings remain read-only.
- Tree-sitter provides bundled syntax highlighting, document structure, and syntax-aware selection expansion for supported languages. This is local syntax behavior, not LSP completion, diagnostics, type information, or cross-file navigation; unsupported languages remain plain text.
- Saves use revision checks and no-clobber installation while retaining Unix owner, group, permissions, ACLs, and extended attributes. Remote conflicts keep the phone draft for an explicit choice; uncertain outcomes are checked and never replayed automatically. The editor history button lets you inspect and explicitly delete durable save-recovery records.
- File writes require the v0.0.20 remote helper and its `fileEditing` capability on Linux or macOS. Older helpers continue to browse and read files without enabling edits.

### Open a remote terminal

- Open a project shell from the terminal button in a session header, with mobile accessory keys, clipboard controls, pinch zoom, horizontal panning and Powerline prompt glyphs. Pinch commits one resize at the end instead of repeatedly reflowing full-screen programs.
- Back returns to chat without stopping the session-owned shell or losing its scrollback and view state. Close ends it; opening an exited shell starts a fresh one.
- Terminal traffic uses a separate bounded SSH channel and never enters Pi RPC, transcripts or model context. Transport loss closes the shell without reconnecting or replaying input.
- Terminal access requires the v0.0.20 helper on a Linux host. Existing and new phone pairings can use it there; activating the helper upgrades the older forced command in place.

### Select and navigate without losing context

- Assistant prose can be selected and copied in place across adjacent paragraphs, lists, and assistant messages, including content around folded thinking and tool activity.
- Markdown styling and links remain active before selection, and links remain tappable.
- The chat and editor expose direct return actions while preserving their independent drafts and retained views. Wrapped live command output now scrolls as one continuous surface without virtual-row jumps.
- Editor, folder, structure, and save actions are arranged for compact phone app bars, with bounded menus and Android keyboard-safe editing.

### Better rendered-page scrolling and connectivity

- Compact rendered HTML previews hand vertical drags back to the conversation, preventing a tall embedded page from trapping nearby chat scrolling. Expanded pages keep their own scrolling.
- A drag or fling over a compact preview no longer turns into an accidental expand tap.
- SSH addresses support bracketed IPv6 hosts and non-default ports. Existing IPv6 host-key pins remain trusted through their legacy address alias rather than falling back to first-use trust.

### Release operations and compatibility

- Android Local continues to bundle Bun **1.4.3** and Pi/Durable SDK **1.3.0**. Install updates in place with the existing signing key; do not uninstall the app or clear its data.
- New phone keys remain inactive until approval is durably published. Concurrent `authorized_keys` generations are retained as private recovery siblings instead of being silently discarded.
- Android Local and Durable remain experimental and unsandboxed. Automated validation uses faux providers and offline fixtures; it does not make live provider requests.
