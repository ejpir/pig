## Android Local fixes

Fixes Local chats getting stuck at prompt admission or reporting that saved state
must be checked, even after signing in.

A fixture-only control message was accidentally forwarded into the production
Durable command stream without a request ID. This stopped the session before the
prompt could be admitted. Production no longer sends that control, and the
Android adapter never forwards it to the SDK.

Existing chats, SQLite history and pending request identities are preserved. On
reopen, retained requests are checked/retried using their original identities;
no clearing of app data or sign-in reset is required.

Regression tests cover the non-synthetic transport with signed-in/out account
metadata, real SQLite admission and duplicate request IDs. Native authorization
is deliberately denied in the tests: no real credentials or live inference.

### Switching providers and signed-out errors

Changing the model/provider in an existing Local chat now keeps its confirmed
model, thinking level and transcript. Configuration and read acknowledgements no
longer replace the committed Durable projection with an empty state.

Failed replies are visible even when the backend does not support file review.
When the selected provider has no signed-in account, the failure explains which
account to sign in to under Local accounts before sending again. Storage,
refresh, cancellation and connectivity failures remain distinct from confirmed
missing sign-in; native diagnostics and credential contents are not displayed.

Offline regressions cover Claude ↔ Codex switching, the failure card, native
missing-account classification and cleanup, saved SQLite history, and duplicate
request IDs after reopen. Sign-in does not automatically resend a failed request.

**Android Local remains experimental**, unsandboxed and not production-security
validated. The stock tool named `bash` uses Android `/system/bin/sh`, not GNU Bash
or a supplied Linux userland. Background/lifecycle execution and arbitrary
mid-tool crash recovery are not guaranteed. Bun 1.4.3 and the unchanged public
Pi/Durable SDK 1.2.0 remain bundled in the normal APK, with runtime/relink archives.
