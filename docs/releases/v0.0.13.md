## Highlights

**Native Visualize now works on desktop and Android with one shared implementation.** Request `@Visualize` in chat to create interactive native tools, diagrams and small games. Controls and animation run locally, without follow-up model calls or a WebView.

### Desktop integration

- A reserved **Visualize** mention-menu action inserts the directive without submitting. Prompt expansion happens before attached file contents; generated mentions, quoted guides and recovered attachment text cannot grant execution permission.
- Completed, opted-in assistant replies render native cards in the transcript. Source viewing, copying, reset and local state are available alongside ordinary Markdown.
- Execution requires unambiguous durable message identities and valid active history ancestry, for both local and SSH sessions. Streaming, failed, aborted, stale or ambiguous replies remain inert. State follows the session, user/assistant entries and exact app source—not row positions or surrounding prose.
- Window blur, hidden cards, navigation and prompts suspend activity and release held input. Stale callbacks cannot mutate replacement apps. Running apps and retained native transcript projections are bounded.

### Shared runtime, renderer and controls

- `pi_visual` owns the portable QuickJS-NG runtime, prompt contract and samples. New `pi_visual_ui` owns GPUI cards, controls, drawing, input, local state and frame scheduling. Android and desktop supply thin platform/navigation adapters rather than duplicated implementations.
- Rich paths, two-stop gradients, transforms/groups, native canvas text and reusable drawing layers. Native geometry caching and subdivision account for device pixel ratio, fitted viewBox scale and composed transforms.
- Keyboard input, held buttons, phased pointers, multitouch and coalesced moves support richer interactions. Legacy gesture cancellation still rolls back its draft; phased cancellation releases physical state without undoing unrelated gameplay. Accessible held-button activation uses a bounded pulse.
- Text-only apps can animate too. Sliders display their labels and current values; shared card chrome retains source, copy and reset controls.

### Native SVG subset

- New `ui.path(svgPathString)`, `ui.svg(xml)` and `g.svg(asset, {x, y, width, height})` APIs support reusable inline vector assets.
- Standard path commands, bounded elliptical arcs, basic shapes, rounded rectangles, groups, viewBox fitting, transforms, inherited paint, source-unit strokes and local two-stop linear gradients lower into native geometry.
- **Not browser SVG:** no images/sprites, external resources, scripts/events, CSS, SVG text/fonts, filters, masks, clipping paths, advanced compositing, or gamepads. Unsupported content fails explicitly. Native canvas text is separate from SVG text.

### Safeguards and compatibility

- Fresh isolated JavaScript contexts, transactional state, a shared 20 ms invocation budget, 16 MiB VM heap and 256 KiB stack limits. SVG source, parsing, cache, scene and path complexity are bounded; native contour/expanded-vertex budgets apply to cache hits and repeated instances too.
- These remain **experimental in-process cooperative safeguards**, not OS isolation or hard real-time guarantees. Native parsing/tessellation is not preemptive; extreme zoom is best-effort.
- Existing JavaScript visuals, historical prompt recognition, legacy dp stroke widths and saved-state schema remain supported. SVG strokes use source units. JSON/Rhai visuals remain non-executable; regenerate them with `@Visualize`. No app-data or credential migration is required.
- Stock Pi and Durable remain pinned to **1.2.0**. This release does not change swarm defaults or the separate browser-backed inline-page feature.

### Validation

Workspace tests, Android UI tests, strict Clippy, real-Pi metadata transport, fake-LSP tests and packaging/tooling checks were exercised locally. Native desktop SVG controls were tested under Xvfb at 1× and 2×, and the extracted Android host at 2×; the ARM64 APK was built and signature/notices checked. Release CI checks the clean pinned dependencies and packages the supported desktop targets and Android APK.

The interim SVG build was installed and cold-launched on the physical phone with app data preserved. That deployment check does **not** establish physical-device SVG quality, presentation FPS or complete lifecycle/resource reclamation. See the [Visualize API and limits](https://github.com/ejpir/pig/blob/v0.0.13/crates/pi_visual/README.md) for the exact supported subset.
