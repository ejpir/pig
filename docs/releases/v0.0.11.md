## Highlights

This release adds experimental host-side schedules and durable peer swarms, improves Android input and output handling, and makes compaction controls reflect the running model.

### Android UI and input

- More reliable first taps and long presses across composer text and padding, including keyboard resize. Tapping a control outside a moving scroll viewport no longer requires an extra tap to stop the fling; taps inside still catch momentum safely.
- A compact subagent composer with a separate Send target, no repeated bold task label, and a shorter **Stop** button. Home's crew icons have more space below the progress rail.
- Selectable tool output with a header Copy icon and a full-width **Ask about this** action.
- Full, live-updating per-call edit diffs, with requested changes distinguished from reported applied changes. Line-number gutters retain padding and align code across digit widths.
- **Schedules** now opens from Home's **Computers** menu. Consent text wraps correctly on narrow screens.

### Durable swarms and subagents — experimental

- Explicit `swarm:true` delegation supports **2–8 parallel, read-only peers** with durable, host-owned mailboxes for findings, questions and correlated replies. Peers receive only read and peer-messaging tools; the coordinator remains the writer.
- Android provides **Map, Exchanges, Agents and Results** views, filtering, exact-peer navigation, Markdown results and confirmed peer Stop. Disconnected screens show last-known observations rather than presenting stale state as live.
- A session-level **Swarm** switch controls admission of new swarms. Disabling it does not stop admitted crews, disable their mailboxes, or block ordinary subagents. Existing sessions without a saved preference retain the previous enabled behavior.
- Original delegated answers remain attached to their original submissions across recovery and later child turns. Finished child conversations are read-only in Android.
- Messaging does not automatically start recipient turns. **Received** means explicit retrieval, not agreement or successful execution. Display history is bounded; this is not a shared editing/worktree or dependency-scheduling system.

### Scheduled runs — experimental

- Configure recurring prompts, projects and models using numeric five-field cron and an explicit IANA timezone. Preview upcoming times, review changes, pause/resume jobs, separately confirm **Run now**, and inspect occurrence history through normal durable sessions.
- Runs happen on an awake **Linux or macOS host**, independently of the phone. Each occurrence gets a fresh session. Same-job overlap is skipped; missed occurrences default to skipping, with optional bounded catch-up once.
- Durable occurrence identities and receipt lookup distinguish admission, execution and outcomes. Recovery does not blindly resubmit uncertain prompts. Pausing or deleting a job preserves existing sessions and project files.
- Host setup is explicit: run `pi-desktop-remote scheduler start` locally. Optional login autostart uses `scheduler install --confirm`; installing it does not immediately start the scheduler. The phone never silently installs or starts host services.

### Compaction and model/session reliability

- Android shows the backend's actual compaction policy instead of a fixed 80% marker. Supported durable sessions can save a background-compaction threshold by dragging the marker in session Details.
- Thresholds use the actual generation model's context window, including subagents, while retaining safety reserves and history. Background compaction is visible without unnecessarily blocking chat.
- Improved context/stat refresh, compaction retry bookkeeping and recovery of retained transcript prefixes. Compaction still requires a safe history boundary and is checked before model requests, not immediately when an idle session crosses a threshold.
- Provider-private streaming buffers are excluded from persisted public messages, including non-JSON Bedrock partials, while preserving public text, tool arguments and signatures.

## Upgrade and safety notes

- Update Android **in place with a compatible signing key**. Do not clear app data or uninstall to work around a signing mismatch: preserve the phone's SSH identity, host credentials and durable session storage.
- Update the computer helper to **v0.0.11**, then reconnect. New runtime capabilities require a **fresh session**; reconnecting an already-running daemon does not replace its runner. Unsupported controls remain unavailable rather than acting as local-only preferences.
- QR pairing, durable swarms and scheduling require the Unix helper; scheduling is supported on Linux and macOS, not Windows. Windows desktop and stock-Pi helper packages remain available.
- Scheduled prompts run with the host account's capabilities and credentials, **not in an OS sandbox**. Read-only instructions alone are not enforcement. Swarm peers have a restricted toolset, but that is not filesystem/process isolation. A timeout requests Stop; it is not a hard execution, cost or security boundary. Admission is not task completion or an exactly-once guarantee for external effects.

## Downloads and validation

Desktop packages and standalone helpers are supplied for Linux AMD64/ARM64, macOS ARM64 and Windows AMD64, plus the Android ARM64 APK and **SHA256SUMS**. Publication is gated on formatting, Clippy, tests, deterministic durable/scheduler checks, native UI validation and the complete build matrix.
