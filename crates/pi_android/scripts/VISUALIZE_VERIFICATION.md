# @Visualize · native Android integration

## Implementation

1. Composer offers the reserved `@Visualize` mention independently of project-file loading. A file named Visualize is offered as a quoted file mention.
2. `prompt_for` expands only the draft, before attachment/review encoding. The admitted payload contains the portable-app contract once. Existing admission IDs, image bytes, queues, retries and transport are unchanged. Display labels and projected user prompts hide the injected contract, retaining the user's original text.
3. Only assistant reply rendering can create mini-apps, after an explicit opt-in turn in that conversation. Ordinary prompts, tool results, compaction summaries and swarm Markdown remain inert.
4. A complete, bounded `pi-visual` block is validated by shared `pi_visual`; native GPUI draws it inline. Streaming EOF is not closure. At most two candidates per turn are attempted, with eight retained runtime instances. Other/invalid/unsupported blocks keep the original code renderer and copy action.
5. GPUI taps call `dispatch` and repaint/remeasure the owning turn. Appending prose does not reset inputs. A turn-wide ordinal normalizes flow/summary rendering. Store/session identity, immutable projected user-message identity, original prompt and bundle revision separate instances. Legacy replies without a user-message identity/timestamp stay inert outside fixtures. Evicted controls re-ensure and restore their captured bundle before dispatch/reset.
6. Source opens the native selectable text sheet without recreating the app. Copy retains raw JSON. Reset is explicit. Successful local state updates are saved in app-private `visual-app-state.json` (32 snapshots / 256 KiB maximum), validated on restore. Fixture previews never write real settings or mini-app state.

## Scope

Version 1: rows/columns/text/buttons with flat primitive state. Version 2 adds bounded native canvas scenes, float-bound sliders, canvas pointer events, and script-controlled tick callbacks. No browser, JavaScript or per-app Rust compilation. No input/repeating-list vocabulary, backend action bridge, state synchronization, permission grants or state migration between changed bundles. The phone must have the reply to restore its runtime; saved state is not a complete offline transcript cache. Opt-in is inferred from loaded user turns, so after history/compaction removes that turn, mention Visualize again.

Rhai exposes selected pure packages and formatting helpers only. Function pointers/curry/anonymous functions, imports and eval are disabled. Operations, recursion, containers, source, view and restored state are bounded. Synchronous in-process limits are not OS process isolation or a production sandbox qualification.

## JavaScript/QuickJS migration (v3)

At the user's request, removed Rhai from dependencies/execution and replaced the escaped JSON envelope with one plain JavaScript program in a closed top-level `javascript pi-visual` fence. `app`/`ui` helpers register native nodes, function callbacks map to host IDs, and shape recording maps to existing GPUI paths. Ordinary JavaScript fences remain inert. Existing JSON/Rhai sources remain inspectable/copyable, with regeneration messaging rather than guest execution; no source or saved-state deletion is performed. Exact admitted v1/v2 guides remain recognized for clean labels/retry identity.

rquickjs 0.14.0 bundles QuickJS-NG 0.16.2. Android enables bindgen with target-specific NDK/Bionic flags; host headers must not be used for cross-target bindings. Both full upstream MIT notices are packaged instead of Rhai notices. Rhai has no entry in the client dependency tree. Guest heap/stack/time limits are cooperative in-process safeguards, not OS sandboxing or exact instruction counting.

Each event, uncached drawing, or computed-text batch reevaluates source in a fresh bounded VM/context; no mutable captures/globals/jobs survive calls. Rust alone owns schema-validated state and validated caches. State uses one numeric Number type; sliders quantize atomically. Text getters are batched/cached separately from state. Numeric no-op state retains scenes. Full completed trace and alternate radii pass. No WebView or per-program Rust build is involved.

Review regressions: native array scans are length-guarded before entering QuickJS C methods (including generic sparse-array calls; separate-process timeout regression protects the test runner); a native Promise creation hook rejects resolved/rejected/unreturned/prototype-altered async work before commit; computed IDs are disjoint/reserved; callback receivers do not expose registration maps; reflection intrinsics are captured; text-batch faults cache once and suspend animation; reserved tick IDs cannot be overwritten; quantization range overflow is rejected; inline HTML does not accidentally opt in; slider mount IDs include reset generation so stale release hooks cannot restore the wrong state. Guarding native methods is not a claim of complete process isolation.

Opt-in aggregate profiling now adds surface-input cadence/coalescing wait, callback/VM/decode, root request-layout through prepaint completion (includes Taffy), root paint/path reuse, native input age, Choreographer wake/service, main-queue CPU work, and GPU-backend acquire/encode+submit/present-call CPU durations. A transparent root element preserves layout IDs/accessibility/gestures. The sibling gpui_wgpu dependency adds only an opt-in CPU timing method; its ordinary draw path does not read clocks. No source/state/coordinates are included in these counters. CPU present calls do not establish actual presentation; system FrameTimeline/Perfetto is still needed for that.
